ACCUEIL
-------
- Des projets qui regroupent le site, le dossier de code, les applications, les scènes 3D,
  les documents et les sites surveillés.
- « Par quoi commencer ? » : vous choisissez un objectif (app Android, logiciel Windows,

==========================================================================================
2. QUELS FRAMEWORKS DEVIENNENT UNE APP ANDROID ET UN LOGICIEL WINDOWS
==========================================================================================

LE PRINCIPE
-----------
NEXORA ne transforme pas votre code en interface native. Il construit la version web de
votre projet (index.html, JavaScript, CSS), puis l'intègre :
  - Android : dans une application native écrite en Java qui affiche le site, avec les
    fonctions natives de window.NexoraApp ; résultat : APK et AAB signés ;
  - Windows : dans Electron, empaqueté par electron-builder ; résultat : installateur,
    version portable, ZIP, MSI, MSIX.

Donc : tout framework capable de produire un site statique fonctionne pour les deux,
hors ligne.

A. CONSTRUITS DEPUIS LE CODE SOURCE, HORS LIGNE, ANDROID ET WINDOWS
-------------------------------------------------------------------

  HTML, CSS, JavaScript (site statique)
      Commande  : aucune
      Dossier   : le dossier qui contient index.html

  Vite avec React, Vue, Svelte, Solid, Preact ou Lit
      Commande  : npm run build
      Dossier   : dist

  Parcel, Webpack, Rsbuild, Rspack
      Commande  : npm run build
      Dossier   : dist

  Create React App
      Commande  : npm run build
      Dossier   : build
      À prévoir : construire avant de choisir le projet dans l'App Builder (partie 4)

  Vue CLI
      Commande  : npm run build
      Dossier   : dist
      À prévoir : construire avant de choisir le projet dans l'App Builder (partie 4)

  Angular
      Commande  : npm run build
      Dossier   : dist/<nom-du-projet>/browser

  Next.js
      Commande  : npm run build
      Dossier   : out
      À prévoir : output: 'export' dans next.config (partie 3)

  Nuxt
      Commande  : nuxt generate (script « generate », sinon npx nuxi generate)
      Dossier   : .output/public

  SvelteKit
      Commande  : npm run build
      Dossier   : build
      À prévoir : adaptateur @sveltejs/adapter-static (partie 3)

  Remix, React Router 7
      Commande  : npm run build
      Dossier   : build/client
      À prévoir : mode SPA, ssr: false (partie 3)

  Astro
      Commande  : npm run build
      Dossier   : dist
      À prévoir : rien (sortie statique par défaut)

  Qwik
      Commande  : npm run build
      Dossier   : dist
      À prévoir : adaptateur statique de Qwik City (partie 3)

  Ember
      Commande  : npm run build
      Dossier   : dist

  Gatsby
      Commande  : npm run build
      Dossier   : public

  Docusaurus
      Commande  : npm run build
      Dossier   : build

  VitePress
      Commande  : vitepress build (souvent npm run docs:build)
      Dossier   : .vitepress/dist ou docs/.vitepress/dist

  Eleventy
      Commande  : npx @11ty/eleventy (ou votre script build)
      Dossier   : _site

  Storybook
      Commande  : npx storybook build (ou npm run build-storybook)
      Dossier   : storybook-static

  Hugo
      Commande  : hugo --minify
      Dossier   : public

  Jekyll
      Commande  : bundle exec jekyll build
      Dossier   : _site

  Expo (React Native)
      Commande  : npx expo export --platform web
      Dossier   : dist
      À prévoir : version web d'Expo (partie 3)

  Flutter
      Commande  : flutter build web --release
      Dossier   : build/web
      À prévoir : version web activée, dossier web/ (partie 3)

Desktop Builder : il reconnaît ces frameworks, propose la commande et le dossier produit,
puis lance la construction. S'il n'y a pas de script « build », vous saisissez la
commande.

App Builder : avec la source « Projet (code source) », le bouton « Construire » lance
npm run build (ou pnpm, yarn) ou flutter build web --release, puis l'App Builder cherche
index.html dans : dist, build, out, www, public, docs, .output/public, build/web et
dist/browser.
  - Si le projet n'a pas de script « build » adapté (Nuxt, Expo, Hugo, Jekyll,
    VitePress...), lancez vous-même la commande indiquée ci-dessus.
  - Si le dossier produit n'est pas dans cette liste (Angular, Remix, React Router,
    VitePress, Eleventy, Jekyll, Storybook), choisissez la source « Dossier construit »
    et désignez le dossier qui contient index.html.

B. FRAMEWORKS QUI ONT BESOIN D'UN SERVEUR
-----------------------------------------
Ces projets fabriquent leurs pages sur un serveur : ils ne peuvent pas être intégrés tels
quels. L'application s'ouvre alors sur l'adresse du site.

  Laravel (y compris Inertia avec Vue, React ou Svelte), Symfony, PHP, WordPress
      Android : reconnus. L'APK s'ouvre sur l'adresse du site en ligne, ou sur un serveur
                de test que NEXORA lance sur votre PC (php artisan serve ou php -S ;
                interface construite d'abord par Vite si elle manque), pour un
                téléphone connecté au même Wi-Fi, tant que le PC reste allumé.
                WordPress : sa base de données MySQL doit déjà tourner (Laragon,
                XAMPP...).
      Windows : adresse du site en ligne (le Desktop Builder refuse le dossier).

  Django, Ruby on Rails
      Android : reconnus ; adresse du site en ligne seulement.
      Windows : adresse du site en ligne (dossier refusé).

  TanStack Start, SolidStart, Flask, FastAPI, Streamlit, ASP.NET / Blazor, Go,
  Deno / Fresh
      Android : adresse du site en ligne (WebView, ou Trusted Web Activity en HTTPS).
      Windows : adresse du site en ligne (dossier refusé).

  Next.js, SvelteKit, Remix ou React Router avec rendu côté serveur, serveurs Node.js
  (Express...)
      Passez à la sortie statique (partie A et partie 3), ou hébergez le site et
      utilisez son adresse. Le Desktop Builder accepte le dossier de Next.js, SvelteKit,
      Remix et React Router, mais prévient que les pages rendues par le serveur ne
      fonctionneront pas sans sortie statique ; pour Nuxt, il lance nuxt generate.
      Un serveur Node.js (Express...) est à héberger, puis à ouvrir par son adresse.

Avec une adresse en ligne, l'application a besoin d'Internet, mais chaque mise à jour du
site apparaît sans republier l'application.

C. PROJETS ELECTRON
-------------------
Un projet Electron existant (electron-builder ou Electron Forge) est construit tel quel
par le Desktop Builder, pour Windows. Avec Electron Forge, NEXORA lance sa commande
« make » et récupère les installateurs produits.

D. CE QUE NEXORA NE CONSTRUIT PAS
---------------------------------
- Android natif (Kotlin ou Java avec Gradle) : refusé (« Application Android native »).
- iOS natif (Swift, projet Xcode) : refusé (« Application iOS native »).
- React Native sans version web : refusé ; ajoutez react-native-web ou passez par Expo.
- Flutter et Expo : c'est leur version web qui est intégrée, pas leur rendu natif.
- iOS : aucune construction (l'App Builder montre seulement un aperçu iPhone).
- macOS et Linux : rien n'est construit sur le PC ; NEXORA génère un fichier
  GitHub Actions qui produit les .dmg, .zip, .AppImage et .deb sur les serveurs de
  GitHub.

3. LE CODE À AJOUTER DANS VOS SOURCES
==========================================================================================

Next.js : fichier next.config.mjs

    /** @type {import('next').NextConfig} */
    const nextConfig = {
      output: 'export',               // produit le dossier out/
      images: { unoptimized: true },  // seulement si vous utilisez next/image
    };
    export default nextConfig;

SvelteKit : installez l'adaptateur, puis remplacez-le dans svelte.config.js (gardez le
reste du fichier)

    npm i -D @sveltejs/adapter-static

    // svelte.config.js
    import adapter from '@sveltejs/adapter-static';
    export default {
      kit: { adapter: adapter() },    // produit le dossier build/
    };

    // src/routes/+layout.js
    export const prerender = true;

React Router 7 : fichier react-router.config.ts

    import type { Config } from '@react-router/dev/config';
    export default { ssr: false } satisfies Config;   // produit build/client/

Remix (avec Vite) : fichier vite.config.ts

    import { vitePlugin as remix } from '@remix-run/dev';
    import { defineConfig } from 'vite';
    export default defineConfig({ plugins: [remix({ ssr: false })] });

Nuxt : fichier package.json

    { "scripts": { "generate": "nuxt generate" } }

Qwik City : adaptateur de site statique

    npm run qwik add static

Expo : version web

    npx expo install react-native-web react-dom @expo/metro-runtime

Flutter : si le dossier web/ manque

    flutter create --platforms web .

Laravel (serveur de test de l'App Builder) : une fois, dans le dossier du projet

    composer install
    copy .env.example .env          (cp .env.example .env sous macOS et Linux)
    php artisan key:generate

  Puis, dans l'App Builder : « Tester depuis ce PC », démarrer le serveur, et « Utiliser
  cette adresse pour l'APK ». Si le pare-feu de Windows le demande, autorisez PHP sur
  les réseaux privés.

Projet Electron : fichier package.json (sinon electron-builder prend index.js)

    { "main": "main.js" }

4. BON À SAVOIR
==========================================================================================

- Pas besoin de régler « base » ni les routes : les fichiers sont servis à la racine
  (https://appassets.androidplatform.net/ sur Android, app://local/ sous Windows) et les
  adresses sans extension des applications d'une seule page (React, Vue, Angular...)
  renvoient vers index.html.
- Règle générale : n'importe quel dossier déjà construit qui contient index.html
  fonctionne, quel que soit l'outil qui l'a produit (source « Dossier construit » dans
  l'App Builder, dossier du site dans le Desktop Builder).
- Create React App et Vue CLI dans l'App Builder : avant la construction, l'App Builder
  trouve le modèle public/index.html de ces projets et affiche quand même « index.html
  trouvé ». Cliquez d'abord sur « Construire » (ou lancez npm run build) : sinon l'APK
  afficherait une page blanche. Défaut noté dans SUIVI.md (A-078), pas encore corrigé.
- Cette fiche décrit ce que fait le code : aucune application n'a été construite pour
  l'établir (les outils Android et Windows ne sont pas disponibles dans l'environnement
  de travail de Figma Make).
